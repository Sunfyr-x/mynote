# 周期挪用为什么导致了cpu访存延迟

这是关键，也是“周期挪用”和“访存延迟”这两个说法最容易引起混淆的地方。

## 核心结论

> **CPU没有延迟已经完成的那一次访存，但通常会延迟紧接着的下一次访存。**

所谓“CPU的访存被延迟”，不是指DMA打断CPU正在进行的那次访存，而是指：

> DMA插入的总线周期，把CPU后续需要使用总线的时刻向后推迟了一个周期。

换句话说，周期挪用会延迟CPU的**下一次总线访问**，不是撤销或推迟已经完成的访存结果。

## 一、已经完成的访存不会倒回去重做

假设CPU本来准备连续进行三次访存：

```
T1：CPU访存 A
T2：CPU访存 B
T3：CPU访存 C
```

DMA在T1之后申请总线，而T1这个访存周期已经开始了。常见处理是：

1. T1正常完成；
2. DMA借用T1结束后的总线窗口；
3. 传一个数据；
4. CPU再在DMA归还总线后执行T2。

结果变成：

```
T1：CPU访存 A
T+：DMA传送
T2：CPU访存 B
T3：CPU访存 C
```

所以：

- **A的访存没有延迟**；
- **A读到的数据也没有被破坏**；
- 被推迟的是B，也就是下一次原本要开始的访存。

严格说，B不是在原时刻“开始得更晚”吗？是的，这才是延迟所在。

## 二、为什么有些教材说“CPU相应延后访存”？

这里的“延后”一般是**概括性说法**，意思是：

> CPU原本连续使用总线的节奏被DMA插入打断了，下一次访存开始时刻向后延后。

不是指某个已经完成的访存被暂停、回滚或重新执行。

如果把时间划分成连续的存储周期：

```
原时序：
S1 S2 S3 S4
CPU CPU CPU CPU

周期挪用后：
S1 S2 S3 S4 S5
CPU DMA CPU CPU CPU
```

CPU在S2本可以继续访存，但DMA先占用了一个总线周期，所以CPU的第二次访存从S2推迟到S3。这就是“访存延迟一个周期”。

## 三、还有另一种解释：CPU自己暂停，不是正在进行的访存暂停

有些教材描述周期窃取时会说：

> DMA请求总线，CPU在完成当前机器周期后暂停访存，DMA占用一个周期。

这里的“暂停”也不能机械理解成：

> CPU把某一次正在进行的读内存操作停在半路。

更合理、更常见的含义是：

1. CPU把**当前正在执行的机器周期**做完；
2. 如果这个机器周期里包含访存，就把它完成；
3. CPU不立即启动下一次访存；
4. 系统把总线交给DMA；
5. DMA传一个数据；
6. CPU再开始下一次机器周期或访存。

所以“暂停访存”指的是：

> **暂停启动新的访存操作。**

## 四、可以把CPU和DMA看成使用同一条通道

假设走廊里只有一条通道：

- CPU原本连续通行：
    
    ```
    CPU → CPU → CPU → CPU
    ```
    
- DMA插入一次：
    
    ```
    CPU → DMA → CPU → CPU → CPU
    ```
    

DMA没有把正在通过的CPU人员拽回来，但：后面准备通过的CPU人员必须等DMA过去。

因此，“CPU访存被延迟”应该理解为：

> **CPU后续访存的开始时间向后推迟了。**

## 五、为什么又强调“等待CPU完成访存”？

这是为了强调DMA通常不会强行拆分一次内存访问。

一次访存一般包括：

- CPU送出地址；
- 发出读/写控制信号；
- 内存完成读写；
- 接收或写回数据。

如果DMA在中间强行抢走总线，时序会非常复杂，也可能造成数据错误。所以通常约定：

> **已经在执行的总线周期由CPU完成，DMA等当前总线周期结束后再申请或获得总线。**

但这不意味着CPU的访存完全不受影响：DMA占据的是CPU原本可以利用的后续总线周期。

## 六、一句话总结

你的质疑本质上是因为两个说法混用了：

- “**CPU完成了当前访存**”   
    → 指当前正在进行、已经开始的那次访存正常结束。
- “**CPU访存被延迟**”   
    → 指CPU后续下一次访存不能立即开始，被向后推迟了一个总线周期。

所以更准确的标准表述是：

> **周期挪用不会中断CPU正在进行的访存，而是等待当前访存周期完成后，由DMA临时占用一个总线周期；CPU后续访存的开始时间会延迟一个周期。**
