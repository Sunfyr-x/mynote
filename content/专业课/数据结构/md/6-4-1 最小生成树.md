## 最小生成树

边权之和最小的生成树

>[!danger] 算法能找出几种MST就有几种MST

## Prim 算法

### 1. 核心思想

从一个起点开始，**逐步把离当前 MST 最近的顶点"拉进来"**，每次选一条连接 MST 与非 MST 的**最小权边**。

### 2. 数据结构

|结构|作用|
|---|---|
|`key[1..V]`|每个顶点到 MST 的最短边权，初值 ∞，起点=0|
|`visited[1..V]`|标记是否已选入 MST|
|图的存储|邻接矩阵（最常用）或邻接表|

### 3. 每一轮的具体操作

```
重复 V 轮：
① 扫描 key 数组，在 visited=false 的顶点中找 key 最小的 → 选入 MST
② 对该顶点的每条邻边 (u,v, w)：
     若 visited[v]=false 且 w < key[v]：
         key[v] = w   （松弛更新）
```

### 4. 时间复杂度推导（邻接矩阵版）

|操作|每轮耗时|轮数|总计|
|---|---|---|---|
|扫描 key 找最小值|第 i 轮比较 V−i+1 次|V 轮|∑i=1V​(V−i+1)=2V(V+1)​=O(V2)|
|更新 key（扫描一行）|每行固定 V 次|V 轮|V×V=O(V2)|

**总复杂度：O(V2)**

> 📌 注意：即使每轮扫描次数递减（你的直觉完全正确），等差数列求和后仍是 O(V2)。

### 5. 堆优化版（了解即可）

- 用**最小堆**存 `(key[v], v)`，找最小值 O(logV)
- 总复杂度 O(ElogV)（邻接表存储）
- 408 不要求推导到这一层，但选择题可能提及

## Kruskal 算法

### 1. 核心思想

**贪心选边**：把所有边按权值从小到大排序，依次尝试加入 MST，**不形成环就保留**。

### 2. 数据结构

|结构|作用|
|---|---|
|边集数组 `Edge[]`|存所有边 `(u, v, w)`，按 w 排序|
|**并查集（Disjoint Set Union）**​|判断两顶点是否已连通，防止成环|

### 3. 具体操作流程

```
① 所有边按权值升序排序
② 初始化并查集：每个顶点自成一个集合
③ 遍历每条边 (u, v, w)：
     若 find(u) ≠ find(v)：
         选入 MST
         union(u, v)
     当选满 V-1 条边时停止
```

### 4. 时间复杂度推导

|操作|复杂度|说明|
|---|---|---|
|边排序|O(Elog2​E)|比较排序的下界|
|并查集 find/union|O(α(V)) 均摊|带路径压缩+按秩合并，几乎常数|
|遍历所有边|O(E⋅α(V))|最多扫完所有边|

**总复杂度：O(Elog2​E)+O(E⋅α(V))=O(Elog2​E)**

> 📌 排序是绝对主导项；并查集操作极快可忽略。

## 三、两算法对比（408 选择题核心）

|维度|Prim（邻接矩阵）|Kruskal|
|---|---|---|
|核心操作|维护 key 数组 + 逐轮选点|排序边 + 并查集判环|
|时间复杂度|O(V2)|O(ElogE)|
|适合稠密图（E≈V2）|✅ V2≪V2logV|❌ 排序代价高|
|适合稀疏图（E≪V2）|❌ 仍是 V2|✅ ElogE≪V2|
|存储结构|邻接矩阵（随机访问 key 快）|边集数组（排序方便）|
|是否需要并查集|不需要|需要|

---

## 四、一句话总结

> **Prim = 维护 key 数组逐点扩张，瓶颈在每轮扫描找最小值 → O(V2)；Kruskal = 排序边 + 并查集判环，瓶颈在排序 → O(ElogE)。稀疏图选 Kruskal，稠密图选 Prim。**
